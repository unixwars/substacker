# A feed reader project, embedded in the app: plan

> **For agentic workers:** use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Test first, one commit per task. Work on a feature branch; never push to `main`.

**Goal:** back up a Substack as static files, read, search and browse it offline in a standalone PWA, with a core library other apps can embed.

**Architecture:** a monorepo (`core`, `scraper`, `shell`, optional `relay`) with the generated content on a protected orphan `content` branch of the same repository. The raw feed items and images are the backup and the only committed content; the served files (posts, index, search) are derived from them on every deploy and published on the Pages site. One workflow scrapes, commits the backup, builds and deploys. An embedding app installs `substacker-core` from a release tarball and renders it with its own components.

**Tech Stack:** TypeScript, npm workspaces, Vitest, Zod, MiniSearch, DOMPurify with jsdom, Vite and React (shell), Playwright, GitHub Actions, a Cloudflare Worker (relay, if needed).

**Spec:** [2026-11-06-newsletter-reader-design.md](2026-11-06-newsletter-reader-design.md)

## Global Constraints

- No publication is named in code, docs or tests. The real feed URL and name live in the `SUBSTACKER_CONFIG` repository variable in CI and in `substacker.config.local.json` locally (gitignored; `substacker.config.example.json` is the committed template, using `example.substack.com`). Feed link, feed name, subscribe link, `actions`, `utmSource`, the `hidden` slugs and the shell address are configuration, never code.
- The core ships no user-facing strings; a host brings its own. English everywhere, including comments and test names.
- Pure logic in `packages/core` with a `.test.ts` beside it. Components render; they do not decide.
- Free tiers only; no backend beyond static hosting and scheduled CI. The scraper never deletes a post, and nothing rewrites the history of `content`.
- Before finishing a task: type check, lint, tests.

## Review Focus

Each line has its test in the task named.

- A feed with zero items, or one item: the index is valid and the shell shows an empty state (tasks 8, 10).
- A title edited on Substack: same slug, same post, no duplicate (task 8).
- A post removed from the feed later: its raw file stays and it stays in the index (task 9).
- A hidden slug: out of the index, the search and previous/next in every reader, back without re-fetching when unhidden; a slug matching nothing is a warning (task 9).
- An image that fails to download: the post publishes, is marked `unlocalized`, and the next run retries it from the raw item (task 9).
- A feed URL that redirects to another host: the run aborts (task 9).
- Hostile or odd HTML, and the Substack widgets as they appear in real feeds (button-wrapper CTAs, `<picture>`, `<svg>`, `<button>`) (task 4).
- Two runs at once, or a run that finds no change: no lost or empty commits (task 12).

## Tasks

1. **Probe, before anything else.** In the new repository, `probes/` with a script and a workflow: from GitHub Actions, fetch the feed and one image of each kind (Substack CDN, its S3 host, a third party), print status and size, and check whether `/api/v1/posts/<slug>` returns a numeric id. Never fail the job. The user runs it and reports; the result settles whether task 11 exists and whether an app action can be revisited.
2. **Scaffold and CI.** Monorepo with npm workspaces on `main`, strict `tsc`, ESLint, Vitest, an orphan `content` branch (one empty commit) with a ruleset blocking force push and deletion (documented; the user applies it), a CI workflow running the three gates, and a release workflow that on a tag runs `npm pack` for `packages/core` and attaches the tarball to a GitHub Release. Add `AGENTS.md` (project rules: strict TypeScript, tests beside pure logic, English only, nothing deployment-specific in code, never rewrite `content`) and a CI step that packs `substacker-core`, installs the tarball in an empty directory and imports every subpath, to catch undeclared dependencies. Commit.
3. **Core contract.** `packages/core/src/contract.ts`: `IndexSchema`, `PostSchema` (with `sourceUrl`, `contentHash`, `unlocalized`), `DocsSchema` (`{slug, title, text}[]`), `CONTRACT_VERSION`, and `parseIndex(json): Index`, `parsePost(json): Post`, `parseDocs(json): Doc[]`, which throw a typed `ContractError` with `reason` `"malformed"` or `"newer"` (a reader accepts versions up to its own). Tests: a good payload, each missing required field, a newer `version`.
4. **Sanitizing and Substack widgets.** `core/src/sanitize-policy.ts` (allowed tags, attributes and URL schemes as data) and `core/src/dom.ts`: `sanitizeHtml(html: string, parse: DomParser): string` on DOMPurify, so the scraper passes a jsdom parser and the readers pass the browser's. `scraper/src/widgets.ts`: `stripWidgets(html: string): string` removes `p.button-wrapper` CTAs whose `href` is subscribe, comments or share (a different button link stays as a plain link), drops `button`, `svg`, `data-attrs` and `class`, turns each `<picture>` into one `<img>` and an iframe into a link to its source. Tests: a hand-made structural fixture item (placeholder text, `example.substack.com` addresses, no real publication content) (the three CTAs go, the figure and caption stay), and a hostile corpus asserting properties of the output (no script, no `on*`, no `javascript:`, no iframe).
5. **Core post logic.** `neighbours(index, slug): { previous?: Entry; next?: Entry }` (the index is newest first, so "next" is older), `canonicalUrl(link: string): string` (drops query and hash), `outboundUrl(url: string, opts: { utmSource: string; action?: "share" }): string` (sets our `utm_source` and `utm_medium=reader`, never the feed's), `dockLinks(post, actions, utmSource): { kind: "comment" | "share"; href: string }[]`, `imageName(url: string): string` (a hash of the address plus its extension; the scraper and the build both use it), and `resolveAssets(html: string, base: string): string` (relative image paths and `cover` to absolute). Tests with exact values, including a feed link carrying `utm_` parameters.
6. **Core search and cache order.** `createSearcher(docs: Doc[]): Searcher` with `Searcher.query(q: string): string[]` (slugs, best first; empty query returns nothing; title outranks body), on MiniSearch. `evictionOrder(entries: {key, bytes, lastOpened}[], capBytes: number): string[]`. Tests: ranking, a prefix, a typo, eviction under, at and over the cap.
7. **Core hooks.** `core/src/react.ts`: `useFeedIndex(base, fetchFn?)`, `useSearch(base, query, fetchFn?)`, `usePost(base, slug, fetchFn?)`, each returning `{ status: "loading" | "ready" | "error" | "unsupported", ... }`; `"unsupported"` is a newer contract; a slug missing from the index is `"error"` with a not-found reason. Tests with a fake `fetch` (jsdom): loading to ready, a network error, a malformed payload, a newer version, a hidden slug.
8. **Scraper and build functions.** `parseFeed(xml: string): { slug, raw }[]` (the raw item serialized as received; `slug` from the link's `/p/<slug>`), `imageUrls(raw: string): string[]` (every image address in a raw item, `<picture>` candidates included), `derivePost(raw: string, present: Set<string>, opts): Post` (stripWidgets, sanitizeHtml, `contentHash`, and each image mapped to `images/<imageName(url)>` when that name is in `present`, otherwise kept as is and counted in `unlocalized`), `buildIndex(posts: Post[], hidden: string[]): { index, docs }` (hidden slugs left out of both). Tests on fixtures: empty feed, one item, a title edited with the same link, a non-ASCII slug, an item whose image file is missing.
9. **Scrape and build commands.** `scrape(config, deps): Promise<Change[]>` (fetch with redirects limited to the feed host; the raw items and missing images to write; writes nothing itself) behind the `substacker-scrape` CLI, and `build(config, backupDir): Files` behind `substacker-build`, which writes the served files to an output directory. Config is resolved by `loadConfig(env, readFile)` from `SUBSTACKER_CONFIG` (JSON in the environment) else `substacker.config.local.json`, validated by Zod, failing with a message that names `substacker.config.example.json` when neither exists (`feedUrl`, `feedName`, `relayUrl?`, `subscribeUrl?`, `actions: ("comment"|"share")[]` defaulting to empty, `utmSource` defaulting to `substacker`, `hidden: string[]` defaulting to empty). Tests: config from the environment, from the local file, the environment winning, neither present, and invalid; a second scrape returns no changes; an edited item changes only its own raw file; a changed sanitizer policy changes the build output with no feed fetch; a failed or malformed fetch and a cross-host redirect return an error and no changes; a post gone from the feed keeps its raw file and its place in the built index; a missing image is retried, and the built post is `unlocalized` until it arrives; hide, unhide, and an unknown hidden slug warning; the build is identical on two runs.
10. **Shell app.** `apps/shell`: Vite and React, hash routes, `config.json` loaded at start (`contentUrl`, `feedName`, `subscribeUrl`, `actions`, `utmSource`), the core hooks, list with search and an empty state, post with previous and next, the dock from `dockLinks`, a Subscribe link, a "read on Substack" link on every post, theme through CSS variables. Playwright against a fixture content directory: list, open a post, previous and next, search, the empty state, a hidden slug is not found, the dock present or absent by config.
11. **Relay, only if task 1 says so.** `apps/relay`: a Worker that fetches the feed URL for callers with a shared-secret header, allowlisted to the feed host only. Tests: wrong secret rejected, another host rejected, the allowed host passes through status and body. Otherwise skip, and say so in the commit of task 12.
12. **Publish workflow.** `.github/workflows/publish.yml` (host per task 1): triggers schedule, dispatch and push to `main`; `concurrency: { group: publish, cancel-in-progress: false }`; `permissions` `contents: write`, `pages: write`, `id-token: write`; create the orphan `content` branch if missing; check out `main` and `content`; run `substacker-scrape`; commit the backup only when something changed; run `substacker-build` into the Pages output; build the shell with `config.json` written from the resolved configuration; `SUBSTACKER_CONFIG` set from `vars.SUBSTACKER_CONFIG`; deploy one Pages site (shell at the root, the served files under `/content/`); report the site size and fail above 800 MB. Test: a dry-run script that runs the same steps against the fixture feed and lists the backup files it would commit (empty on a second run) and the files it would deploy.
13. **Shell offline.** `apps/shell` service worker: a precache list generated at build time, Vite base from the environment, cache names and IndexedDB keys prefixed from the base path with cleanup limited to that prefix, stale-while-revalidate for `index.json` and `search.json`, cache-on-open for posts and images, a configurable cap (default 50 MB) using `evictionOrder`, last-opened times in IndexedDB, and an "available offline" marker. Playwright: open a post, go offline, reload, the post opens; an unopened post says it is not available offline; with a low cap the oldest is evicted; a second shell on the same origin keeps its caches.
14. **Docs and release.** README and `docs/setup.md`, the forking and setup guide (first, resetting a copied `content` branch to a single empty orphan commit; then set the `SUBSTACKER_CONFIG` repository variable from `substacker.config.example.json`, enable Actions and Pages, the ruleset, what to do if the schedule lapses, serving the shell under a path, the contract policy), then version, tag `v0.1.0`, and the first release with the tarball.
15. **Before any PR.** The checklist from the spec's "Needs a real service or a person" section, given to the user as numbered commands and what a pass looks like. Backfill and the Substack-app action are follow-up issues.
